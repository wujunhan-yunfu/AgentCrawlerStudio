# AGENTS.md

## Project Overview

Xvfb + headed Chrome + Pillow screen capture via WebSocket to a browser-based Playwright control UI.
Python 3.12+, FastAPI backend, React+Vite+Monaco frontend.

## Developer Commands

```bash
# Build frontend (required after any frontend change, before running backend)
./build.sh

# Run backend (requires static/ to exist — build.sh creates it)
./run.sh              # background, log: .app.log
./stop.sh             # stop

# Frontend dev (hot reload, proxies /api/v1 to backend at 8080)
cd frontend && npm run dev

# Backend directly (foreground)
uv run python -m backend.main

# Backend tests + coverage (pytest; ~560 tests, 90%+ backend coverage)
uv run pytest
uv run pytest --cov=backend --cov-report=term   # coverage report
```

## Architecture

- **Backend entry**: `backend/main.py` → `create_app()` → FastAPI app
- **Services**: `backend/services/` (capture, browser, cdp, console, network, dom, storage, lsp, crawler, sandbox, save, agent)
- **Routers**: `backend/routers/` (console, control, lsp, stream, agent)
- **Frontend build output**: `static/` (not checked in, generated by `build.sh`)
- **Frontend dev server**: port 5173, proxies `/api/v1` → `127.0.0.1:8080`
- **Default API prefix**: `/api/v1`

## Build Notes

- `build.sh` runs in order: (1) generate lib API indexes via `.venv/bin/python frontend/scripts/generate_*.py`, (2) `npm install --prefix frontend`, (3) `npm run build --prefix frontend` (runs `tsc -b && vite build`)
- The `frontend/src/libApi.json` and `playwrightApi.json` are **generated files** — do not edit manually; regenerate with `build.sh` or the scripts directly

## Key Quirks

- Chrome runs **headed** with `--no-sandbox` (safe for root/CI); starts on Chrome's default blank page (no URL argument)
- `Xvfb` display defaults to `:99`; backend auto-reuses existing Xvfb if `:99` is already held
- Each `/run` request spins up a **fresh browser** with a new temp `user-data-dir` (non-incognito — incognito breaks the CDP Cookie API); Xvfb + capture are kept
- Code execution sandbox: file I/O via `open`/`os`/`pathlib`/`shutil`/`subprocess`/`io`/`tempfile`/`glob`/`sys` etc. is blocked; only `save_content`/`save_page` write files
- **Dev limit** is ON by default (`--dev-limit`/`DEV_LIMIT=1`); `--no-dev-limit` for full data
- `crawler_id` defaults to empty (Agent falls back to `"default"`); set via `--crawler-id` or `CRAWLER_ID` env var for login ticket / session isolation
- Agent is a **unified session-based multi-turn chat** (no crawler/code type split); sessions + messages persist to MongoDB per `crawler_id`
- LLM defaults: provider=`deepseek`, model=`deepseek-v4-flash` (override via CLI or env)
- `llm_api_key` must be provided for Agent features (400 error if missing)
- MongoDB: `mongodb://127.0.0.1:27017`, db=`crawler` (configurable via `--mongo-uri`/`--mongo-db`)

## Tests

- Backend unit tests in `tests/` (pytest + pytest-asyncio, mongomock for Mongo; no real Xvfb/Chrome/Mongo needed)
- Routers are tested via a fake-service app factory in `tests/conftest.py` (`make_test_app`) with `httpx.ASGITransport`
- Agent (`runner.py`/`run_login.py`/tools/login/middleware) uses in-memory fake store/agent; LLM/Mongo are mocked
- Coverage is configured in `pyproject.toml` (`[tool.coverage.run]`, `main.py` omitted)
